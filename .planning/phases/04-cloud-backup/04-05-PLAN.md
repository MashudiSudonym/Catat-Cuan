<objective>
Fix the Google Sign-In blocker (UAT Test 2) by deleting the redundant scope-check two-step in AuthServiceImpl.signIn().

Purpose: The UAT found that tapping "Hubungkan Akun Google" throws UnimplementedError because signIn() calls a scope-check API that is unimplemented on the google_sign_in platform interface (it requires serverClientId, which is intentionally not set). This two-step block is fully redundant — the drive.appdata scope is already declared in the GoogleSignIn constructor at service_providers.dart:99-101, and signIn() requests constructor-declared scopes automatically during the OAuth flow. The fix is a pure deletion of ~14 dead lines. No new code, no new config, no API substitution. This unblocks UAT Tests 3–12 (all blocked-by Test 2).

Output: AuthServiceImpl.signIn() that completes the OAuth flow using the constructor-declared scope, verified green by flutter analyze + flutter test.
</objective>

**Resulting signIn() body (after deletion):**
```dart
  @override
  Future<Result<AuthUser>> signIn() async {
    try {
      // Trigger interactive sign-in
      final googleUser = await _googleSignIn.signIn();
      if (googleUser == null) {
        return Result.failure(
          AuthCancelledFailure('Pengguna membatalkan masuk'),
        );
      }

      return _buildAuthUser(googleUser);
    } on PlatformException catch (e, stackTrace) {
      AppLogger.e('Google sign-in platform error', e, stackTrace);
      return Result.failure(_mapPlatformException(e));
    } catch (e, stackTrace) {
      AppLogger.e('Google sign-in failed', e, stackTrace);
      return Result.failure(
        const AuthUnknownFailure('Gagal masuk ke akun Google'),
      );
    }
  }
```

**PRESERVE (do not touch):**
- The `// Trigger interactive sign-in` comment on the signIn line (existing — not added by this task).
- The full try/catch chain — the catch-all still maps to `AuthUnknownFailure('Gagal masuk ke akun Google')`, satisfying AGENTS.md Rule 4 (never expose technical errors to UI).
- `signOut()`, `getSignedInUser()`, `refreshToken()`, `_buildAuthUser()`, `_mapPlatformException()` — unchanged.
- No changes to `service_providers.dart` — the constructor scope is already correct and is the sole, authoritative scope declaration.

**Why no replacement:** `GoogleSignIn.signIn()` requests all scopes declared in the constructor during the OAuth consent flow. The deleted block was never reachable on this platform interface (it threw before any scope logic ran) and added zero behavioral value even if it hadn't thrown. Adding `serverClientId` to enable the dead API would be scope creep against an intentional architectural decision (no server-side client). The constructor scope is the correct, idiomatic, working pattern.
